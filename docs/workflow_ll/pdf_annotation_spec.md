# 标注 PDF 的规范（颜色 + 底色/下划线）

> 目标：让你在 **回看/复盘/写笔记** 时，能用最少的颜色和最少的视觉噪声，快速定位：结论、证据链、疑问与风险、参数设置、转折与对比。

## 1. 总原则（保证页面整洁）

1) **同一处内容默认只用一种标注**：优先“底色”或“下划线”其一，避免反复叠加。
2) **底色负责“扫一眼的结构”**；下划线负责“精确定位的点”

- 底色：句子/结论/段落级（1–3 行以内）
- 下划线：词/短语/符号级（术语、变量、数值、限定词、对比对象）

3) **宁可少、不要满页**：标注是索引，不是再排版一遍。
4) **语义要唯一**：一个颜色尽量只表达 1 个核心含义；如果必须复用，用“符号”区分（见第 4 节）。

## 2. 颜色语义（推荐“唯一含义”版本）

你现在的用法整体合理，但有两处容易“语义过载”：**红色**、**紫/洋红**。下面给出一版更易复盘的映射（可在保持你习惯的前提下微调）。

| 颜色 | 建议主语义（尽量唯一）                   | 典型标注对象                                     | 建议形态                             |
| ---- | ---------------------------------------- | ------------------------------------------------ | ------------------------------------ |
| 红   | **问题/风险/缺陷/必须回答的疑问**  | 方法弱点、实验漏洞、不可复现点、你明确不信的结论 | 下划线为主，必要时小块底色           |
| 黄   | **关键结论/要点（第 2 级）**       | 摘要/结论句、方法核心步骤、主要实验发现          | 底色为主                             |
| 绿   | **优势/亮点/可复用的做法**         | 新颖点、工程技巧、清晰的 ablation、可迁移结论    | 底色或下划线（看粒度）               |
| 蓝   | **论证链条/逻辑结构**              | 定义→假设→推导→结论、因果关系、证明结构       | 底色（短块）                         |
| 紫   | **超参/设置（具体值）**            | 学习率、batch、窗口长度、损失权重、表格设置列    | 下划线（圈“值/范围”）              |
| 洋红 | **对比/消融结论（哪个更好）**      | “A 优于 B”/敏感性趋势/最优设置结论             | 底色（结论句）+ 必要的下划线（数值） |
| 橙   | **转折/边界条件/例外**             | however/but/although；only if/under；limitations | 下划线（只划转折短语）               |
| 灰   | **背景/定义/以后再看**（低优先级） | 常识性背景、相关工作入口、术语定义               | 轻量底色或不标                       |

> 如果你坚持保留“红=最高级重要点”，建议用 **符号** 把红色再细分（见第 4 节），否则回看时会把“重要”与“问题”混在一起。

## 3. 底色 vs 下划线：具体操作规则

### 3.1 底色（填充底色）

**用在：句子/结论/段落级索引（1–3 行以内）**

- 结论句（尤其是 “we propose / we show / results indicate”）
- 方法核心步骤的“总结句”
- 实验主要发现（表格/图附近的解读句）
- 逻辑段落的“承上启下句”（可配合蓝/橙）

**避免：**

- 整段连续涂满（超过 3 行就应拆分或只涂关键一句）
- 公式区域大块涂色（容易降低可读性）
- 同一句话里多颜色叠底（除非你有明确的复盘需求）

### 3.2 下划线

**用在：词/短语/符号级精确定位**

- 变量名、符号、关键术语（第一次出现）
- 超参取值/范围/约束（尤其在表格或实现细节段）
- 限定词（only/assume/bound/under）与边界条件
- 对比对象（baseline 名称、数据集、指标、训练设置差异）
- 转折词（橙色只划转折短语即可）

**避免：**

- 把整行当作下划线单位（会变成“视觉噪声”）
- 同一段里对每个术语都下划（只划“你需要回看时定位的那几个”）

### 3.3 允许叠加的唯一推荐场景

当你已经用 **底色** 标了一个结论句，但你需要“钉住”其中的 1–2 个关键点（数值/变量/对比对象）：

- 结论句：底色（黄/绿/洋红/蓝）
- 关键点：在句内对 1–2 个词/数值加下划线（紫/洋红/橙等）

> 规则：**同一个底色块内，下划线不超过 2 处**。

## 4. 符号体系（用来减少颜色叠加）

为避免”颜色语义过载”，建议用短符号做二级区分（写在句末或页边即可）：

### 4.1 基础符号

- `？`：疑问 / 需要回答
- `!!`：高风险 / 明显缺陷 / 可能推翻结论
- `TODO`：后续要验证（复现、查引用、跑代码）
- `↔`：需要对照（与另一页/另一篇/另一个设置）
- `△`：值得借鉴但需改造（可迁移点）
- `★`：值得引用（写论文时需要 cite）
- `⊕`：支持我的假设/研究方向
- `⊖`：与我的假设/结论矛盾

示例（推荐写法）：

- 红色下划线 + `？`：这句话我不信，为什么成立？

- 绿色底色 + `💡`：核心创新，值得借鉴
- 紫色下划线 + `⚙️`：关键超参设置

## 5. “整洁度”硬约束（建议照做）

为了让每页可读、可扫：

- **每页底色块 ≤ 6 个**
- **每个底色块 ≤ 3 行**
- **同一段落最多 2 种颜色**
- **下划线以“短语/数值”为单位**（不要整行）

如果某页标注超标：优先删掉“背景/重复/显而易见”的标注，只保留能服务复盘的索引。

## 6. 论文各部分的标注侧重

| 论文部分              | 主要颜色  | 标注重点                                               |
| --------------------- | --------- | ------------------------------------------------------ |
| Abstract              | 黄        | 核心结论 1–2 句，`💡` 标创新点                      |
| Introduction          | 蓝 + 橙   | 逻辑链条（gap → motivation → contribution）、转折    |
| Related Work          | 灰 + 绿   | 低优先级扫读；绿色标与自己研究直接相关的               |
| Method                | 蓝 + 紫   | 算法流程（蓝）、关键公式/参数（紫）、`🔬` 标核心设计 |
| Experiments           | 洋红 + 紫 | 对比结论（洋红）、设置值（紫）、`📊` 标关键表格      |
| Ablation              | 洋红 + 绿 | 哪个组件重要（洋红）、可复用做法（绿）、`🧪`         |
| Discussion/Limitation | 红 + 橙   | 局限性（红）、边界条件（橙）、`⚠️`                 |
| Conclusion            | 黄        | 与 Abstract 对照，确认 claim 是否一致                  |

## 7. 标注工作流（从阅读到复盘）

0) **预读（2 min）**：看标题 → Abstract → 所有 Figure/Table 的 caption → Conclusion。判断是否值得精读。
1) **第一遍快速读**：只用黄/蓝/橙（结构+转折+要点），不做红色深度质疑。
2) **第二遍精读**：补绿（优势/可复用）、补紫/洋红（设置/对比结论），对关键疑点加红 + `？/!!`。
3) **批注整理**：用 emoji 在 comment 中写简短说明（`💡`/`⚠️`/`🔄` 等），方便后续检索。
4) **复盘输出**（推荐）：每篇最终只留 5–10 个”可复用结论/缺陷/关键设置”，其余标注可淡化或删减。

## 8. 常见错误与修正

- 错误：红色既表示“重要”又表示“缺陷” → 修正：红色固定为“问题/风险”，重要性用 `!!` 或黄色层级解决。
- 错误：紫和洋红都标“参数” → 修正：紫=设置值；洋红=对比结论（哪个设置更好）。
- 错误：底色块太大 → 修正：只涂结论句；其余用下划线钉关键词。

## 9. 一页速查（最小可执行版）

- 黄：结论/要点（底色，≤3 行）
- 蓝：逻辑链条（底色，小块）
- 绿：优势/可复用（底色或下划线）
- 红：问题/风险（下划线 + `？/!!`）
- 紫：超参设置值（下划线）
- 洋红：对比/消融结论（底色 + 关键数值下划线）
- 橙：转折/边界（只划转折短语）
- 灰：背景/以后再看（可不用）

### 10.2 文本替换（原生 app 最高效）

`System Settings → Keyboard → Text Replacements`（系统设置 → 键盘 → 文本替换）

以 `;` 开头设置缩写，输入后按空格自动替换：

```
;idea  → 💡    ;key   → 🔑    ;aim   → 🎯    ;pin   → 📌    ;star  → ⭐
;lab   → 🔬    ;data  → 📊    ;up    → 📈    ;down  → 📉    ;gear  → ⚙️
;test  → 🧪    ;q     → ❓    ;warn  → ⚠️    ;flag  → 🚩    ;think → 🤔
;idea2 → 💭    ;link  → 🔗    ;vs    → ⚖️    ;loop  → 🔄    ;ok    → ✅
;no    → ❌    ;write → ✍️    ;note  → 📝    ;file  → 🗂️    ;tag   → 🏷️
```

> **适用范围**：仅在支持 macOS 原生 `NSTextView` 的 app 中生效（Notes、TextEdit、PDF Expert、Safari、Mail 等）。Zotero、Chrome、VSCode 等非原生 app 不支持，需使用 10.1 emoji 面板或从剪贴板文件复制。

### 10.3 Zotero 用户推荐方案

Zotero PDF 阅读器使用自有渲染引擎，**不支持 macOS 文本替换**。推荐方案：

1. **Emoji 面板**（首选）：`Ctrl + Cmd + Space` 在 Zotero 批注框中可用
2. **剪贴板文件**：打开 `docs/workflow_ll/emoji_clipboard.md`，直接复制粘贴所需 emoji
3. **输入法工具**（进阶）：使用 Raycast / Alfred 等工具的 Snippet 功能，可在所有 app 中触发替换
